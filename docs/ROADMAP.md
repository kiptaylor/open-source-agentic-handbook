# Roadmap

The handbook grows through small, reviewable releases.

## Operational in v1

- Canonical agent, skill, policy, guide, release, compatibility, and request
  registries
- Orchestrator, watchdog, context steward, security governor, verifier, and
  bounded worker profiles
- Task-envelope, context, handoff, policy, scope-expansion, manifest, lock,
  request, approval, and update-plan contracts
- Core, optional, and downstream project-owned skill buckets
- Prompt and portable-bundle generation from one small project manifest
- Local request export with a transport-neutral envelope
- On-demand drift check, plan, approval, apply, validation, and history
- Synthetic orchestration scenarios, link checks, structural validation, and
  public-safety scanning

## Next

- Publishable package or release artifact for easier generator installation
- GitHub issue and pull-request adapters that preserve the v1 request envelope
- Signed or authenticated approval adapters
- Stronger JSON Schema instance validation and compatibility fixtures
- Companion views generated directly from a project manifest and lock
- More synthetic failure, recovery, compaction, and policy-gateway evaluations

## Later

- Thin provider and runtime adapters kept separate from durable guidance
- Reference policy gateway and bounded orchestrator implementations
- Richer release evidence and interoperability test suites
- Optional status and evaluation feeds for companion sites

No always-on control service, autonomous publication, remote request backend, or
runtime permission gateway is promised by v1.
